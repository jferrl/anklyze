<objective>
Surface ambiguous and impossible classification flags in API responses and frontend UI.

Purpose: Users must always know when a classification is uncertain (ambiguous) or invalid (impossible). Currently, ambiguous results without `possible_types` render as regular cards (silent failure), and impossible results hide all classification data behind an early-return Alert. Both violate the core value: ambiguous and impossible cases must be clearly surfaced, never silently dropped.

Output: Backend domain type with `AmbiguousReasonKey` field, engine paths populated, frontend ClassificationResult.tsx updated to show warning/error banners for all ambiguous/impossible cases, i18n strings in both locales.
</objective>
