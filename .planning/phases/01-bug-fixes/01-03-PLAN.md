<objective>
Make database fallback mode explicit in API responses and server startup logs.

Purpose: When the database is unavailable, the server silently falls back to NoOp repositories and the `/health` endpoint returns `{"status": "ok"}` with no indication of degraded mode. Callers (monitoring, frontend, other services) cannot distinguish a fully healthy server from one running without a database. This plan adds a `db` field to the health response so callers can detect degraded mode.

Output: Health endpoint returns `{"status": "ok", "db": "healthy"}` or `{"status": "ok", "db": "degraded"}` based on whether the database connection succeeded at startup. Handler constructor accepts a `dbHealthy` parameter.
</objective>
